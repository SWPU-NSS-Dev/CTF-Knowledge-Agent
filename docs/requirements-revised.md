# 任务修订：模块化采集与性能优先

本文件记录用户在原开发任务基础上提出的调整。完整系统目标仍为：多源发现 → 持久任务 → 原文与版本 → 本地检索 → 本地 AI / RAG → AWDP 知识关系与管理界面。先交付第一阶段可运行知识库。

## 调整后的运行参数

- 不设置固定的网站数、文章数、数据库容量、采集生命周期或知识量上限。
- `max_items: null` 表示持续发现至来源耗尽。HTML `max_depth` 未设置时不人为截断深度。
- 来源并发、全局 worker 数、重试次数、超时和响应大小均通过配置设置；不对这些参数添加任意数值上限。
- `requests_per_second: 0` 表示不插入主动限速延迟；网站返回的重试时间用于调度队列。
- `max_items` 控制本次发现量；`max_jobs` 控制本次 worker 处理量。后台 worker 可以继续处理已经入库的任务。
- 实测报告分别记录网络采集耗时、本地入库吞吐量和检索延迟。性能数字必须同时给出数据量、环境与测试方法。

原文快照、版本证据、访问边界、凭证保护和采集代码不自动执行属于数据与运行正确性保障，继续保留。

## 网站插件

每个网站以独立 Python 模块实现 `SourceAdapter`，提供 discover / fetch / parse / normalize / validate。网站自己的目录结构、分页、正文选择与增量规则放在插件内；队列、数据库、API 和检索复用核心实现。

核心不枚举插件的全部配置字段，网站参数放入 `options`。新增插件支持两条接入路径：

1. 本地配置中的 `adapter: package.module:AdapterClass`，用于项目内或本地安装模块。
2. 安装包通过 Python entry point 组 `ctfka.sources` 注册，适配器注册表自动发现。

HTTP API 可以选择已注册插件；安装或导入新的 Python 插件通过本地可信配置完成。仅增加插件与配置即可接入网站，不修改调度、存储或 API 实现。

## 实施分工

主代理负责架构、共享契约、代码审查、集成与验收。实际功能代码和修复由 GPT-6 Luna 子代理实现。项目包含 `.codex/config.toml` 与 `.codex/agents/luna-worker.toml`，保存这一分工所需的模型配置。

## 第一阶段交付边界

交付真实公开来源采集、Markdown/HTML 解析、SQLite 版本存储与迁移、持久队列、全文检索、CLI、REST API、插件机制、备份恢复和离线测试。Ollama、Embedding、RAG、OpenAI 兼容对话、AWDP 关系、人审与完整 Web UI 在后续阶段实现，不以静态结果或占位接口代替。
